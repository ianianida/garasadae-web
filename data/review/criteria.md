# Codex 전수 검수 지침 v1

판정 대상은 `data/source/krv-full.json`의 모든 절 번호다. 자료 확보·형식 검사는 의미 검수가 아니다. 각 절 전체를 앞뒤 문맥과 함께 읽고 판정한다. 정규식·단어·장르만으로 자동 제외한 결과를 전수 의미 검수로 표시하지 않는다.

사용자는 신앙인 또는 성경에 거리낌 없는 사람이 가볍게 고민을 적고, 딱 한 번 뽑은 말씀에서 뜻밖의 실마리·신비함·재미를 느끼며 자신의 선택으로 마음을 정하는 경험을 원한다. 고민과 바로 또는 잠시 생각하면 연결되는 절은 허용한다. 단순 관련성, 일반적인 위로, ‘그래서 뭐하라는 건데’ 같은 반응은 충분함과 다르다. 즉시 크게 후련하지 않아도 첫 결과를 받아들일 수 있으면 후보가 될 수 있다.

원래 원하는 방향에 동의할 필요는 없다. 구매를 권하는 개인 해석과 절제를 읽는 개인 해석이 모두 가능하다. 하나님이 직접 행동을 명령한다고 서비스가 해설을 붙이지 않는다. 현실 결과를 보장하지 않고, 문맥의 본래 의미와 개인의 연결을 분리한다. 도덕적 판정이나 설교를 제품의 답으로 만들지 않는다.

본문 전체의 읽기 난이도, 어떤 선택 부담을 건드리는지, 뒷문장이 연결을 깨는지, 입력에 없는 조건을 지어내야 하는지를 판단한다. 역사적 서사도 자연스러운 개인 연결이 가능하면 검토한다. 특정 인물에게만 주어진 명령, 이름·지명 나열, 앞 절이 없으면 의미가 성립하지 않는 단편, 풀이를 많이 요구하는 절은 구체 사유로 보류 또는 제외한다. 장르 자체로 일괄 판정하지 않는다.

`data/review/scenarios.json`의 80개 생성 고민과 대조한다. 필요하면 검수 작업별 추가 생성 고민 파일을 만들 수 있다. 실제 사용자 반응으로 표기하지 않는다. 후보마다 적어도 한 구체 고민에서 원문 전체를 읽고 얻을 실마리와 연결을 방해하는 부분을 적는다. 카테고리 단어만 맞는 연결을 충분하다고 만들지 않는다.

## 특히 보존할 반례

- 실제 지출 여력 부족과 비싼 구매의 죄책감은 다르다.
- 할인 마감에 쫓김·사용 불확실함과 이미 원했고 잘 쓸 물건은 다르다.
- 내일 걱정과 오늘 마감의 미완료 일은 다르다.
- 실제로 돈이 필요한 기한과 빨리 팔고 싶음·계속 확인하는 피로는 다르다.
- 이미 한 거래 약속을 가격·속도만의 갈등으로 바꾸지 않는다.
- 이미 부드럽게 말해도 반복된 위반을 다시 무조건 부드럽게 말하라는 후보로 보내지 않는다.
- 상대의 마음·다음 기회·판매 성공 등 미확인 조건을 긍정 또는 부정으로 확정하지 않는다.

## 검수 결과 파일

각 작업은 배정된 책별로 `data/review/books/<CODE>.json`을 작성한다. 다른 작업 파일·서비스 코드·Git·비밀 파일은 수정하지 않는다. 각 책 파일의 형식은 다음과 같다.

```json
{
  "bookCode": "GEN",
  "corpusSha256": "manifest의 corpusSha256",
  "criteriaVersion": "garasadae-corpus-2026-10-08-v1",
  "reviewer": "Codex 작업명",
  "method": "direct-codex-reading",
  "entries": [
    {
      "id": "KRV:GEN:1:1",
      "textSha256": "해당 본문 해시",
      "status": "candidate 또는 hold 또는 exclude",
      "reason": "이 전체 절이 생활 고민의 실마리를 주거나 주기 어려운 구체 이유",
      "contextNote": "앞뒤에서 무슨 역할을 하는 절인지",
      "readability": "clear 또는 thinkable 또는 needs_explanation",
      "connections": [
        {
          "scenarioId": "생성 고민 식별자",
          "clue": "사용자가 원문에서 읽을 수 있는 선택의 실마리",
          "friction": "전체 문장의 약점. 없으면 빈 문자열",
          "expectedEnough": "yes 또는 uncertain 또는 no"
        }
      ]
    }
  ]
}
```

후보에는 `expectedEnough=yes`인 구체 조합을 적어도 하나 남긴다. `hold`는 보류 사유를 그대로 남겨 최종 검토자가 읽게 한다. `exclude`에도 해당 본문을 읽고 확인한 사유를 남긴다. ‘없음’ 13개는 빈 본문 제외로 별도 처리한다. 본문 해시는 원문에서 채우되 상태·이유는 읽고 평가한 뒤 기록한다. 파일 생성만으로 직접 의미 평가했다고 주장하지 않는다.

모든 절의 개별 검수가 끝나기 전에 작업 완료라고 보고하지 않는다. 진행 보고는 실제 읽고 판정해 저장한 수와 남은 책으로 한다. 보조 프로그램은 읽을 범위 표시·해시 채우기·누락 검사에 사용하며 판단을 대신하지 않는다.
