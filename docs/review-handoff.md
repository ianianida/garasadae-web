# 검수 중단과 재개

사용자는 2026-10-19에 토큰 부족으로 중간에 끊길 수 있음을 고려해 작업하라고 했다. 개별 판정은 20–40개 단위로 즉시 저장한다. 읽기만 하고 판정 파일에 저장하지 못한 항목은 완료가 아니다.

## 재개할 때

1. Git 브랜치와 변경 상태부터 확인하고 기존 변경을 보존한다. 현재 작업 브랜치는 `codex/launch-v1`이다.
2. `npm run review:status`로 실제 1차 원장의 저장·미저장·형식·해시를 확인한다.
3. `node scripts/integration-status.mjs`로 실제 통합 판정의 누락과 다음 읽기 위치를 확인한다. 책 하나는 끝에 `EXO`처럼 책 코드를 붙인다. 이 도구는 의미를 판정하지 않는다.
4. `node scripts/read-integration-range.mjs EXO 시작번호 20 --reading`처럼 전체 구절과 앞뒤 문맥을 다시 읽고 구체 고민·반례와 대조한다. 시작번호는 전체 절 번호가 아니라 그 책의 1차 후보·보류 목록 안의 1부터 시작하는 순번이다.
5. 직접 쓴 다음 `integration-책코드-번호.json`을 저장하고 `node scripts/record-integration.mjs 파일경로`로 통합한다. 이 도구도 판정을 만들지 않고 직접 쓴 판정에 원문 해시를 연결한다.
6. 진행 기록을 갱신하고 의미 있는 묶음마다 Git 커밋·push 후 원격 커밋과 비교한다. 비밀 키·환경 파일·임시 QA 자료는 포함하지 않는다.

새 1차 담당을 인계할 때는 `scripts/review-ledger.ts`의 실제 형식을 먼저 읽는다. `readability`는 `clear`·`thinkable`·`needs_explanation`이다. `easy`는 의미가 비슷해도 허용 표기가 아니므로 사용하지 않는다. 2026-10-21 인계 예시의 잘못된 표기를 담당자들이 `clear`로만 고쳤고 의미 판정은 보존했다.

- 통합 판정 3,083건. 창세기·출애굽기·레위기·민수기·신명기·여호수아·역대상·역대하·에스라·느헤미야·에스더의 모든 1차 후보·보류와 사사기 앞의 90건 재검토를 저장했다.
- 출애굽기: 후보·보류 399건 전부 저장했다. 후보 150, 보류 249건이다. A023의 명시적 기혼 관계로 기존 20:14 제외 전제를 고쳤고 1차 원장 및 `integration-exo-017.json`에 이유를 남겼다. 새 절 읽기 수는 늘리지 않았다.
- 레위기는 후보·보류 228건 전부 저장했다. 후보 73, 보류 154, 제외 1건이다. R019–R021 생성 사례를 추가했으며 새 R021 대조에 따른 레위기 6:7 수정은 작성 파일과 통합 원장 양쪽에 반영했다.
- 민수기의 후보·보류 427건 전부를 통합 저장했다. 후보 128, 보류 299건이며 마지막은 `KRV:NUM:36:9`이다.
- 신명기의 후보·보류 659건 전부를 통합 저장했다. 후보 227, 보류 432건이고 마지막은 `KRV:DEU:34:12`이다. 최초 제외 300건은 1차 원장에 보존한다. 6:18–19·15:4–5·30:9–10의 공식 합친 본문은 각 슬롯을 읽되 추첨에서 같은 본문을 중복 표로 세지 않는다.
- 여호수아 후보·보류 356건 전부(후보 134·보류 222)를 저장했다. 마지막은 `KRV:JOS:24:32`이고 최초 제외 302건은 1차 원장에 보존한다. 사사기 390건 중 앞의 90건(후보 31·보류 59)을 저장했고 마지막은 `KRV:JDG:5:31`이다. 다음 통합 읽기는 `node scripts/read-integration-range.mjs JDG 91 20 --reading`의 `KRV:JDG:6:2`이다. 현재 통합 작업에서 읽기만 하고 판정을 저장하지 못한 범위는 없다. 실제 파일의 다음 위치가 이 메모보다 우선한다.
- 통합 작업용 다음 작성 파일은 `data/review/integration-jdg-004.json`이다. 이미 존재하면 통합 여부부터 확인한다. R022–R027(기도 마음 전하기·오랜 신뢰와 이례적 지각·익숙한 집과 비교·후임 인수인계·남에게 배정된 자리·시작할 준비가 된 작은 모임)은 생성 사례이며 실제 반응이 아니다.
- 이 시점 1차 저장 22,620/31,102개, 완독 저장 36권, 형식·해시 오류 0건을 확인했다. 부분 저장분은 사무엘상 660절(마지막 25:11)·이사야 785절(40:19)·사도행전 100절(4:1)이고 요한복음 879절은 전부 저장했다. 사무엘상 원문의 실제 분모는 809절이다. 이는 의미 검수나 만족도 검증 수치가 아니다.
- 새 A038(식사와 공부)·A039(익숙하지 않은 새 도구)·A040(집을 비울 때 부모 돌봄 부탁)은 첫 담당의 생성 사례다. 여호수아 13:1·14:11의 나이 격려는 R005에 대조하되 A030의 실제 한계를 지우지 않았고, 22:22의 결백은 실제 발송 기록이 있는 R015에 대조했다. 20:5의 선한 의도를 모르는 친구의 마음으로 보태지 않았다.
- 사사기 4:18의 초대를 진실한 돌봄으로 평가하는 데에는 뒤의 살해가 주는 문맥 마찰을 남겼다. 4:19·5:25는 같은 장면에서도 요청자의 실제 필요 표현과 제공자의 의도를 구별해 H033과 대조했다. 악역이라는 역할만으로 발화를 일괄 보류하지 않는다. C018(세례 준비와 과거 잘못)은 별도 새 생성 사례다.
- 사용자가 G05의 오늘 마감인 미완성 과제에도 L·O·M을 충분하다고 한 반응을 유지한다. 신명기 12:18은 G04(일을 마침)와 G05(마감이 남음)를 별도로 대조했다. 마감의 존재만으로 누림의 구절을 자동 보류하지 않으며, 일이 끝났다거나 기한이 바뀌었다는 사실도 추가하지 않는다. 이 새 조합은 실제 반응이 아닌 사전 예상이다.
- 사용자의 잠시 중단 요청은 곧 ‘아니다 진행해’로 철회됐다. 기존 세 병렬 작업도 중단 안내를 철회하고 재개했다. 현재 작업을 계속하라는 지시가 유효하다.
- 2026-10-21 사용량 한도 오류로 세 작업이 종료된 뒤, 현재 사용 가능 상태(`ordinaryUsageAllowed: true`)를 도구로 확인해 기존 세 작업을 재개했다. 재개 첫 미저장 위치는 사사기 5:7, 잠언 31:17, 요한복음 1:31이었다. 오류 기록만 보고 새 작업을 중복 생성하지 말고 현재 원장을 확인한다.
- 이후 에스겔–계시록 작업에서 08:10 재시도 안내가 다시 나왔지만 12:19 KST에 현재 사용 가능 상태를 확인했다. 기존 세 작업에 실제 원장의 첫 미저장 위치(사무엘상 1:1·이사야 11:11·요한복음 9:25)를 전달했다. 이사야 담당은 중단하지 않고 계속 진행 중임을 확인했다. 실행 안내와 실제 저장을 구별하며 새 작업을 중복 생성하지 않는다.
- 이후 기존 세 작업이 실행 목록에 없고 각각 `interrupt_agent` 결과도 `not_found`임을 확인했다. 사용자가 승인한 동일한 세 범위를 `review_gen_resume`(창세기–열왕기하), `review_wisdom_resume`(역대상–애가), `review_nt_resume`(에스겔–요한계시록)으로 이어받았다. 현재 이 세 작업만 실행 중임과 새 판정 저장을 확인했다. 새 범위·유료 API·중복 담당은 추가하지 않았다. 예전 역할명으로 재개를 반복하지 말고 현재 실행 목록과 실제 파일을 먼저 확인한다.
- 2026-10-24 위 이전 여섯 작업이 실행 목록에 없고 세 `*_resume` 대상도 각각 `interrupt_agent`의 `not_found`임을 확인했다. 현재 같은 세 범위의 담당은 `review_gen_oct24`·`review_wisdom_oct24`·`review_nt_oct24`이다. 첫 인계는 사무엘상 11:3·이사야 26:10·요한복음 15:6이며 실제 저장이 그 뒤로 진행됨을 확인했다. 요한복음 완료 뒤 사도행전으로 이어 갔다. 오래된 역할명 대신 현재 목록과 원장을 확인한다.
- 이후 위 `*_oct24` 세 작업도 실행 목록에서 사라지고 각각 `interrupt_agent`가 `not_found`임을 확인했다. 현재 일반 사용 가능 상태를 도구로 확인한 뒤, 같은 세 범위만 `review_gen_cont24`·`review_wisdom_cont24`·`review_nt_cont24`이 이어받았다. 첫 위치는 사무엘상 22:11·이사야 37:13·사도행전 2:25였으며 새 저장을 확인했다. 사라진 원인을 확인 없이 사용량 한도라고 단정하지 않는다.
- 전체 원문은 `data/source/krv-full.json`과 고정 해시를 유지한다. 자동 원문 대조 완료와 사용자 경험 검수 완료를 구분한다.
- 전체 검수·후보 통합·실제 ② 규칙 연결·출시 검사·최종 흐름 확인은 아직 남았다. 공개 배포는 아직 하지 않았다.

## 계속 지킬 판단 기준

공식 기준은 `docs/product-plan.md`, `docs/interview-summary.md`, `docs/full-corpus-review.md`와 사용자의 현재 대화다. 구체 고민과 말씀 전체를 대조한다. 생성 사례의 예상 충분함을 실제 사용자 만족으로 표시하지 않는다. 약속·개인적 비유 자체만으로 보류하지 않되 서비스가 하나님의 명령이나 실제 결과의 보증을 덧붙이지 않는다. 모르는 상대의 마음·새 재고·수입·기한을 사실로 추가하지 않는다. 어려운 뒷말을 삭제해 후보로 만드는 것도 금지한다.
