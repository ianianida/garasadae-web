# 말씀 분류와 구체 조합 검수 초안

> 2026-10-08 공동 검토 자료. 사용자의 ‘다음’ 요청에 따라 기존 평가를 분류 초안으로 정리했다. 후속으로 결정한 개별 조합의 후보 포함, 첫 뽑기의 반복 회피, 다시 뽑기의 직전 구절 제외·후보 확장, 충분한 후보의 동일 확률 추첨은 별도로 표시한다. 데이터베이스 형식·세부 후보 선정과 확장 조건·점수·통과 기준은 공동 결정 사항이 남아 있으며 아직 구현하지 않았다.

## 1. 분류할 기록 세 가지

| 기록 | 담을 내용 | 현재 근거 |
|---|---|---|
| 고민 | 주제, 선택지, 각 선택의 바라는 점과 부담, 기한, 명시된 조건, 알 수 없는 조건 | 사용자가 입력한 원문 |
| 말씀 | 절과 판본, 확인한 출처·본문 버전, 실제 제시 범위, 앞뒤 문맥, 여러 주제와 표현 | 공식 본문과 문맥 검토 |
| 구체 고민 × 말씀 | 어떤 조건의 고민에 제시했는지, 사용자가 읽은 실마리와 선택, 신비함·후련함·충분함, 노출 조건 | 생성 사례에 대한 예상 반응 또는 실제 고민의 기획 단계 평가 |

초기 ②에서 AI는 고민 기록을 원문 근거와 함께 정리한다. 말씀 기록·연결 기록을 런타임 AI에 주어 순위를 매기거나 채택 여부를 판단하게 하는 것은 ③ 확장이다. 서비스는 피드백을 수집·내보내고, 사용자가 Codex에 전달한 자료를 함께 검토해 기록과 규칙을 개선한다.

‘이 말씀은 구매 허용’, ‘이 말씀은 방문 금지’처럼 구절에 행동 결론을 고정하지 않는다. **사용자가 실제로 읽은 선택 방향은 조합의 관찰 결과**로 남긴다. 여러 주제·여러 해석이 가능하다는 이유만으로 후보를 배제하지 않는다.

## 2. 고민 기록에서 함께 볼 정보

| 정보 | 구체 예시 | 해석의 경계 |
|---|---|---|
| 주제 | 구매, 일정·이동, 판매, 관계 | 하나의 주제로만 분류할 필요 없음. 주제만으로 말씀 적합함을 결정하지 않음 |
| 선택지와 바라는 점 | 자켓을 보고 가져오기 / 이번에는 다녀오지 않기 | 선택 개수나 어느 방향이 옳은지 정하지 않음 |
| 각 선택의 부담 | 사면 죄책감 / 안 사면 아쉬움 | 원문에 없는 죄책감·긴급성을 만들지 않음 |
| 기한과 시간 관계 | 당일 과제 마감, 다음날 복귀, 이후 3주 일정, 할인 종료 | 현재의 해야 할 일과 미래에 예상하는 부담을 함께 보존함 |
| 명시된 제약·불확실함 | 남은 생활비 부족 / 자주 입을지 모름 / 판매 여부를 모름 | 비싸다는 감정과 실제 지출 제약을 같은 정보로 처리하지 않음 |
| 이미 기울어진 마음 | ‘친구 덕에 갈 마음이 어느 정도 생김’ | 입력에 명시된 경우에만 기록함. 친구가 권했다는 사실만으로 단정하지 않음 |
| 원문 근거·알 수 없는 조건 | 해당 표현과 인용 위치, 이동 시간·자금 여력의 미확인 | 추정과 명시된 사실을 구별함. 미확인 조건을 없다고 채우지 않음 |

어떤 부담이 결정적인지 입력에 드러나지 않을 수 있다. 후속 평가에서 확인한 부담을 최초 입력 당시 이미 알았던 것으로 바꾸지 않는다. 추가 확인 질문 없이 뽑는 경계는 유지한다.

## 3. 말씀과 연결 기록에 남길 정보

- 말씀: 판본·절 번호·출처, 제시한 정확한 범위, 본문 확인 상태와 이용허가 상태를 각각 기록한다. 개역개정이 우선이며 이전 개역한글 평가를 개역개정으로 소급하지 않는다. 본문을 확인한 표본과 서비스용 데이터셋 확보를 구분한다.
- 연결 근거: 사용자의 어떤 표현과 말씀의 어떤 부분이 연결됐는지 남긴다. 어시스턴트의 연결 가설과 사용자가 직접 읽은 연결을 구별한다.
- 경험: 자연스러운 연결, 신비함, 즐거운 놀라움, 실마리, 즉시 후련함, 나중에 예상하는 후련함, 첫 결과의 충분함을 따로 기록한다. 하나의 합산 점수는 아직 제안하지 않는다.
- 평가 상태: 확인한 반응은 사용자 표현을 보존하고, 말하지 않은 항목은 미확인으로 남긴다. 설명 전·풀이 뒤, 첫 비교·반복 비교, 진행 중 고민·끝난 고민의 회고, 생성 사례·서비스 사용 후 피드백을 구별한다.
- 적용 범위: 같은 구절의 긍정·부정·미확인 조합을 함께 연결한다. 검토한 사례와 다른 상황에 적용할 조건·반례는 제안으로 표시한다. 아직 검토하지 않은 사례에 결과를 예측해 채우지 않는다.
- 문맥: 원문의 뜻·맥락과 개인의 상황 해석을 별도로 남긴다. 일부 표현에 연결이 있어도 제시한 전체를 읽은 반응을 보존한다. 부분만 잘라 보여주는 화면을 확정한 것은 아니다.

## 4. 이미 받은 반응으로 채운 예시

| 구체 조합 | 확인한 반응 | 분류에서 보존할 차이 |
|---|---|---|
| 구매 001 × A · 디모데전서 6:8, 개역한글 | 최고는 아니지만 자연스럽고 신비하며 후련함 | 여러 방향으로 읽을 여지가 있어도 긍정적일 수 있음 |
| 구매 002 × D · 잠언 25:16, 개역한글 | 연결돼 신기하고 구매 의향은 커지나, 자주 입을지의 망설임이 남음 | 연결·행동 의향과 고민 해소는 다른 항목. 충분함은 미확인 |
| 구매 003 × F · 잠언 19:2, 개역한글 | 신비함·보류 의향, 즉시 후련함은 없으나 나중에 기대함. 이 말씀으로 충분함 | 즉시 후련함과 나중에 예상하는 후련함을 구별함 |
| 관계 001 × G · 잠언 25:15, 개역한글 | 뜻을 물은 뒤, 가벼운 시도라면 적절하고 신비해 먼저 부드럽게 연락할 것 같음 | 풀이 뒤의 반응. 원문만 읽은 첫 결과의 성공으로 처리하지 않음 |
| R003 × J · 마태복음 6:28, 개역한글 | 첫 부분은 연결되지만 뒤 부분 때문에 전체로는 다시 뽑고 싶을 수 있음 | 선택 방향이 나와도 충분한 결과는 아닐 수 있음 |
| R003 × L · 마태복음 6:34, 개역개정 | 신비롭고 후련하며 최고의 뽑기일 수 있음 | 다음날 복귀 걱정을 내일의 자신에게 맡기는 실마리 |
| R002 × L · 마태복음 6:34, 개역개정 | 연결·느낌은 약하지만 친구 덕에 이미 갈 마음이 있어 성공적이고 충분했을 것 같음 | 약한 느낌과 불만족을 같게 보지 않음. 당시 기울어진 마음이라는 조건 |
| R004 × M · 잠언 21:5, 개역개정 | 신비롭고 후련하며 최고의 뽑기였을 것 같음 | 빨리 팔기 위해 가격을 낮출지의 망설임이 조급함을 다룬 말씀에 연결됨 |
| R001 × N · 누가복음 12:34, 개역개정 | 자연스럽고 좋은 연결, 신비하고 후련할 것 같음 | 보물을 가족·고등학교 친구들로 읽고, 본가에서 더 큰 행복과 재미를 예상함 |
| 생성 G08 × M · 잠언 21:5, 개역개정 | 연결·신비함과 높은 가격으로 시작하는 실마리, 필요한 돈의 기한 때문에 후련함 없음 | 기한이 가까워지면 다시 뽑을 가능성과 개인적으로 기대한 빠른 판매를 구별함. 충분함은 미확인 |
| 생성 G05 × L · 마태복음 6:34, 개역개정 | 콘서트에 가고 과제도 어떻게든 해보는 실마리, 신비함, 크게 후련하지는 않지만 괜찮은 뽑기. 첫 결과로 충분하다고 예상함 | 오늘 마감인 일이 미완료여도 신비함과 실마리를 읽음. 연결점이 좋아 다시 뽑을 필요가 없다는 평가 |
| 생성 G05 × O · 전도서 3:13, 개역개정 | 조금 어렵고 L보다 연결은 약함. 공연과 과제 중 어느 쪽인지 애매하지만 즐거움에 관한 부분에서 콘서트에 가는 실마리, 약간의 신비함, 나쁘지 않고 다시 뽑을 필요 없음 | 여러 해석의 여지·이해 난도가 있어도 단독 결과로 받아들일 수 있었음. 후련함은 미확인 |
| 생성 G05 × M · 잠언 21:5, 개역개정 | 연결은 있지만 좋은지는 확신하지 못함. 콘서트를 빠지고 과제하기 또는 콘서트에 가고 늦게 제출하기를 떠올림. 조금 신비롭고 후련할 것 같으며 괜찮을지도 모른다고 예상함. 첫 결과라면 그대로 둘 것 같음 | 읽은 두 방향·전체 평가의 불확실함과 첫 결과를 받아들일 수 있음을 함께 보존함. 지각 제출의 허용·결과는 입력에 없는 조건 |

근거: [생성 사례의 사전 검토](verse-review-examples.md), [사용자가 제시한 실제 고민의 검토](real-concern-review.md). 위 자료는 구현된 추첨의 성공률이나 다른 사용자의 만족도 자료가 아니다. ‘좋았음’만 남기면 원래 알 수 없던 조건, 설명의 영향, 같은 말씀의 다른 경험이 사라질 수 있다.

## 5. 범위를 검토할 생성 고민 12개

아래는 어시스턴트가 만든 **생성 사례**다. 실제 사용자의 추가 고민이 아니며, 제시하지 않은 조합에 정답 행동이나 말씀 적합함을 지정하지 않았다. 먼저 검토를 시작할 네 주제이며 서비스가 받을 고민의 범위를 제한하는 목록은 아니다. G08 × M과 G05 × L에 대한 반응을 받았으며 [평가 상태와 반응](verse-review-examples.md)에 별도로 기록한다. 나머지는 아직 사용자에게 대조하지 않았다.

| 주제 | ID | 사용자 입력으로 대조할 고민 초안 | 구별할 조건 |
|---|---|---|---|
| 구매 | G01 | 사고 싶은 자켓이 있고 쓸 돈도 따로 모아뒀다. 자주 입을 것 같지만 최근에도 옷을 샀다는 생각 때문에 마음이 걸린다. 안 사면 아쉬울 것 같다. | 지출 여력과 활용은 명시됨, 최근 구매에 대한 부담 |
| 구매 | G02 | 같은 자켓이 갖고 싶지만 이번 달 생활비가 부족하다. 사면 다른 지출을 줄여야 하고, 이번에 놓치면 언제 다시 살 수 있을지도 모르겠다. | 실제 지출 제약, 다음 기회의 불확실함 |
| 구매 | G03 | 평소 관심 없던 헤드폰이 오늘까지만 할인한다. 이미 쓰는 헤드폰이 있는데 새것을 자주 쓸지는 모르겠다. 할인을 놓치기는 아깝다. | 할인 압박, 활용 불확실함, 다른 물건으로 바꾼 고민 |
| 일정·이동 | G04 | 주말 콘서트가 보고 싶다. 오늘 할 일은 마쳤지만 다녀오면 내일 출근할 때 피곤할까 걱정된다. 이번을 놓치면 다시 볼 기회는 모른다. | 오늘의 여유, 미래에 예상하는 피로 |
| 일정·이동 | G05 | 오늘 콘서트에 가고 싶은데 오늘 마감인 보고서를 아직 못 끝냈다. 다녀오면 작성 시간이 거의 남지 않는다. 표가 아깝고 공연도 보고 싶다. | 명시된 미완료 업무와 당일 기한 |
| 일정·이동 | G06 | 휴일에 부모님을 뵐지, 오늘만 열리는 축제에 갈지 고민된다. 부모님은 다음 달에도 뵐 수 있지만 지금도 보고 싶다. | 두 기회의 비대칭, 관계와 경험 사이의 선택 |
| 판매 | G07 | 카메라를 높은 가격에 올려뒀는데 빨리 팔려면 가격을 낮춰야 할 것 같다. 급히 돈이 필요한 건 아니지만 매일 문의를 확인하는 게 지친다. | 돈의 시급성은 낮음, 기다리는 과정의 부담 |

| 관계 | G10 | 친구에게 내가 말을 심하게 한 건 인정한다. 사과하고 싶은데 먼저 연락하면 민망하다. 더 멀어지기 전에 연락할지 고민된다. | 자신의 잘못을 인정함, 먼저 연락하는 부담 |
| 관계 | G11 | 친구가 약속을 계속 어겨서 부드럽게 말해봤지만 반복됐다. 이번에도 넘어갈지, 분명하게 말하고 거리를 둘지 고민된다. | 이전 시도와 반복된 문제 |
| 관계 | G12 | 친구가 하루 동안 답장을 안 한다. 바쁜 건지 내게 화가 난 건지는 모른다. 한 번 더 연락할지 기다릴지 고민된다. | 상대의 상태가 미확인, 연락과 기다림의 선택 |

같은 주제에서 조건을 바꾸는 대조 외에, 같은 갈등을 다른 물건·활동으로 바꾸거나 뜻을 유지한 표현 바꾸기도 검토한다. 어느 대조에서 후보가 같아야 하는지는 미리 정답으로 지정하지 않는다. 바뀐 핵심 조건을 해석이 보존하는지와 실제 경험이 어떤지를 확인한다.

## 6. 이 자료를 후보 규칙으로 옮기는 절차 제안

1. 고민의 원문·조건을 정리하고 여러 말씀을 별도로 대조한다. 사용자가 받을 때처럼 연결 해설 없이 원문과 출처를 먼저 제시한다.
2. 받은 반응을 조합별로 남긴다. 생성 사례의 예상 반응, 실제 고민의 기획 평가, 배포 후 실제 피드백을 구별한다.
3. 좋은 조합이 성립하는 조건과 다른 조합의 실패·차이를 함께 검토한다. 조건이 다른 사례와 표현을 바꾼 사례에서 범위를 확인한다.
4. 후보의 필수 조건·배제 조건·통과 기준을 사용자와 결정한 뒤, ②의 규칙에 반영한다. AI의 현재 고민 해석만으로 말씀별 좋고 나쁨을 새로 평가하지 않는다. 후속으로 정한 충분한 후보의 동일 확률 추첨을 적용한다.
5. 적용한 데이터·규칙 버전과 피드백을 연결해 내보낸다. 개선은 서비스 밖에서 Codex와 함께 검토한다.

후보가 부족하면 범위를 넓혀 말씀을 제공하며 재뽑기는 직전 구절을 제외하는 방향과, 남은 충분한 후보의 동일 확률 추첨을 후속으로 결정했다. 구체 확장 조건, 동일 구절의 식별 형식·여러 연결 근거의 보존 방식, 충분함을 통과 기준에 반영하는 방법은 공동 검토한다. 관련된 상세 제안은 [고민 해석과 말씀 연결](concern-analysis-matching-proposal.md)을 따른다.

## 7. 실제 고민과 조건을 바꾼 생성 사례의 대조

연휴 본가 방문과 빈티지 팝업 고민 R001에 N(누가복음 12:34, 개역개정)을 제시했다. [대한성서공회 공식 본문](https://bible.bskorea.or.kr/bible/NKRV/LUK.12)에서 절·문장·판본·인접 문맥을 확인했다. 사용자는 보물을 가족과 고등학교 친구들로 읽어 본가가 더 행복하고 재미있을 것 같으며, 자연스럽고 좋고 신비하고 후련할 것 같다고 답했다. 이미 본가에 간 결과를 정답이나 말씀의 효과로 처리하지 않는다.

다음으로 생성 사례 G08에 M(잠언 21:5, 개역개정)을 연결 해설 없이 제시했다. 실제 가격 고민 R004에서는 필요한 돈의 시급성을 확인하지 못했지만, G08에는 이번 주에 필요한 돈이라는 기한을 명시했다. 사용자는 연결이 잘 되고 신비하지만 후련하지는 않을 것 같다고 답했다. 처음에는 높은 가격으로 시작해 기다리되 기한이 많이 다가오면 다시 뽑을 수 있다고 예상했다. 같은 판매 주제라는 이유로 R004와 동일한 경험으로 처리하지 않는다.

## 8. 기한·기대·재뽑기를 구별할 추가 제안

- 평가한 시점과 입력에 명시된 기한·현재 상황을 함께 보존한다. 기한이 가까워져 다시 뽑을 수 있다는 예상과 실제 재뽑기 사건을 구별한다. 남은 일수·가격 등록 상태를 임의로 채우지 않는다.
- 사용자가 기대한 현실 결과와 말씀에서 읽은 실마리를 별도로 남긴다. G08에서는 높은 값에도 빠르게 팔릴 것 같다는 믿음이 생겼지만 이는 거래 결과의 확인이나 서비스의 보장이 아니다.
- 첫 결과의 불만족 때문에 다시 뽑는 것과, 상황이 달라져 다시 뽑는 것을 피드백 분석에서 구별하자는 제안이다. 재뽑기 여부만으로 앞선 결과의 실패를 집계하지 않는다. 구체 수집 방식·화면·질문은 미결정이다.
- 같은 고민의 AI 해석을 재사용하더라도 기한·조건이 달라진 경우를 어떻게 반영할지는 공동 결정한다. 매번 AI를 다시 실행하거나 자동으로 후보를 바꾸는 규칙을 확정한 것은 아니다.

G08에 대해 기한까지 팔리지 않았다면 좋은 뽑기였는지의 평가가 어떻게 바뀔지 추가로 물었다. 사용자는 당시 좋은 뽑기였다면 당시 경험을 기준으로 볼 수 있고, 이후 결과도 일부 영향을 주지만 당시의 연결·신비함·후련함이 무엇보다 중요하다고 답했다. 실제 배포 후 피드백·시장 결과로 집계하지 않는다.

## 9. 후속 대화에서 확인한 평가 중심과 기록 기능

좋은 뽑기의 평가 중심은 **말씀을 만난 당시의 연결·신비함·후련함**이다. 이후 현실 결과가 평가에 일부 영향을 줄 수 있다는 설명도 함께 보존한다. 처음의 경험 평가와 나중 결과·후일담을 각각 기록할 수 있게 한다.

사용자는 이후 결과나 후일담도 기록 기능으로 남길 수 있게 하자고 요청했다. 최소 기록은 고민·말씀·날짜와 당시 생각 또는 결정 한 줄이며, 후일담은 원할 때 남기는 선택적 기록이다. 편집·추가 방식, 공개 범위, 기록을 피드백 분석에 포함하는 방법은 공동 결정 사항이다. 작성 의무·알림·정해진 기간 뒤 설문은 채택하지 않았다.

중대한 고민은 사용자 본인이 면밀히 생각해야 한다는 설명과, 서비스가 결론·하나님의 직접 명령을 대신 말하지 않는 기존 경계를 함께 보존한다. 점수·후보 자격·가중치·통과 기준의 구체 방식은 여전히 제안 단계다.

### 가장 먼저 확인하는 조건 대조

L에 대해서는 ‘오늘의 선택을 막는 내일의 걱정’과 ‘오늘 끝내야 하지만 아직 못 끝낸 일’을 구별해 검토한다. 기존 R002는 당일 마감만 명시됐고 과제의 미완료 상태·남은 작업량은 알 수 없다. G05에는 오늘 마감인 보고서의 미완료와 콘서트 후 작성 시간이 거의 남지 않는 조건을 명시했다. R002의 반응을 G05의 반응으로 대신 채우지 않는다.

G05 × L은 연결 풀이 없이 같은 한 절과 출처를 제시하고, 사용자가 어떤 느낌과 선택의 실마리를 얻을지 질문했다. 사용자는 일단 콘서트에 가고 과제도 어떻게든 해보겠다는 생각, 신비함, 크게 후련하지는 않지만 괜찮은 뽑기라는 예상 반응을 답했다. 후속으로 첫 결과가 충분하며 연결점이 좋아 다시 뽑을 필요는 없다고 답했다. ‘크게 후련하지 않음’을 후련함 전혀 없음이나 결과 불만족으로 바꾸지 않는다.

이 반응은 L을 미래 걱정이 명시된 고민에만 적용하거나, 오늘 마감인 미완료 업무가 있으면 일괄 제외하는 규칙의 근거가 되지 않는다. 사용자에게는 원문의 시간 표현과 실제 고민의 시간이 정확히 일치하지 않아도 실마리와 신비함이 생길 수 있었다. 이를 모든 당일 마감 고민의 성공으로 확대하지 않고, 선택 방향·느낌·충분함을 분리해 검토한다.

사용자는 다른 사용자도 기본적으로 한 번 뽑고 그 말씀을 받아보려는 마음이 있을 것이라고 설명했다. 한 번의 만남을 신뢰하는 이용 기대에 관한 사용자 가설로 기록한다. 여러 사람에게 확인된 이용 행태나 재뽑기 기능을 없애자는 결정은 아니다. 충분한 첫 결과를 목표로 하되 품질이 부족하면 다시 뽑을 수 있도록 하자는 기존 방향을 유지하며, 세부 정책은 공동 결정한다.

질문 전에는 ‘내일의 걱정과 오늘 끝내야 할 일을 구분하는 게 도움이 되는지 확인한다’는 검토 목적을 알렸다. 앞선 L의 긍정 반응과 검토 목적에 노출된 생성 사례 평가라는 조건을 함께 기록한다. 실제 콘서트 참석·보고서 제출·기한 준수 여부는 미확인이다.

### 초기 ②의 규칙과 연결하는 방식 제안

1. AI가 현재 입력의 시간 관계·양쪽 부담·명시된 조건을 원문 근거와 함께 정리한다. 미확인 조건은 없다고 바꾸지 않는다.
2. 서비스 밖의 검토에서 말씀별 연결 조건과 근거 조합을 작성하고, 긍정·부분적 만족·불충분함·미확인을 함께 검토한다.
3. 사용자와 채택한 조건만 프로그램의 후보 규칙에 반영한다. 현재 입력에 대한 말씀별 적합성 평가를 런타임 AI에 맡기지 않는다.
4. 최종 후보에서 추첨하는 확률과 같은 구절의 여러 연결을 합치는 방식은 별도로 공동 결정한다. AI의 고민 해석이 원하는 행동 결론을 정하지 않도록 한다.

이 초안을 검토하면서 어떤 조건을 필수로 요구할지, 어떤 조건에서는 다른 후보와 대조할지, 후보가 부족하면 어떻게 처리할지를 함께 정한다. 조건별 반응을 확인하는 현재 대화는 사전 검수이며, 실제 서비스에서 뽑기 전에 추가 질문을 넣는 방식이 아니다.

## 11. 같은 고민에서 후보 묶음을 검토하기

다음 진행에서는 같은 입력에 여러 말씀을 하나씩 대조한다. 각 말씀이 실제 첫 결과였다고 가정한 예상 반응을 먼저 기록하고, 그 뒤에 첫 결과의 충분함을 확인한다. 앞선 말씀과 비교해 더 좋다는 평가와 단독 결과로 충분하다는 평가는 별도로 보존한다. 한 사용자의 반복 비교이므로 독립된 첫 추첨 실험으로 집계하지 않는다.

| 고민 | 말씀 | 단독 결과로 가정한 반응 | 후보 묶음 검토 상태 |
|---|---|---|---|
| G05 · 콘서트와 오늘 마감인 미완료 보고서 | L · 마태복음 6:34, 개역개정 | 신비함, 두 일을 모두 해보는 실마리. 크게 후련하지는 않지만 괜찮으며 첫 결과로 충분함 | 이 고민의 검수 후보 묶음에서 O와 함께 유지. 다른 사용자 반응·유사 입력으로의 적용 범위·선정 규칙은 미확정 |
| 같은 G05 | O · 전도서 3:13, 개역개정 | 조금 어렵고 L보다 연결은 약함. 콘서트와 과제 중 어디에 연결할지 애매하지만 즐거움에 관한 부분에서 콘서트에 가는 실마리. 조금 신비하고 나쁘지 않으며 다시 뽑을 필요 없음 | 사용자가 이 정도의 말씀도 후보에 넣기로 결정함. 후련함은 미확인. 단독 결과의 충분함·개인적 실마리를 근거로 함께 유지 |
| 같은 G05 | M · 잠언 21:5, 개역개정 | 연결은 있지만 좋은지는 확신하지 못함. 과제를 하며 콘서트에 안 가기 또는 콘서트에 가고 늦게 제출하기를 떠올림. 조금 신비롭고 후련하며 괜찮을지도 모른다고 예상함. 첫 결과라면 그대로 둘 것 같음 | 첫 결과를 받아들일 수 있는 확장 후보로 검토 유지. L·O와 같은 강도의 긍정이나 다른 고민의 자동 후보 자격으로 바꾸지 않음 |

O는 [대한성서공회 전도서 3 공식 본문](https://bible.bskorea.or.kr/bible/NKRV/ECC.3)에서 13절의 정확한 문장, 개역개정 표기와 앞뒤 문맥을 확인했다. 이 장에서 삶의 기쁨과 수고하며 누리는 즐거움을 다루는 문맥을, 개인의 콘서트 참석·과제 제출을 보장하는 결론으로 바꾸지 않는다. 서비스용 데이터셋 도입·사용허가의 확보와 소규모 본문 확인을 구별한다.

같은 전도서 3:13은 이전 구매 고민 001에 B로 제시했으나, O는 개역개정 본문과 다른 고민에 대한 새 조합이다. B의 연결 어려움으로 O를 미리 탈락시키거나 O의 새 반응을 이전 B의 반응으로 바꾸지 않는다. 고민과 판본이 함께 달라져 역본 변경의 효과만 분리해 확인할 수는 없다.

O에서 사용자는 조금 어렵고 L보다 연결이 약하며 콘서트에서 쉬는 쪽인지 과제로 수고하는 쪽인지 애매하다고 답했다. 그럼에도 즐거움을 하나님의 선물로 읽어 콘서트에 갈 것 같고, 나쁘지 않으며 다시 뽑을 필요는 없고 조금 신비하다고 평가했다. 후련함·과제에 대한 부담 해소·과제 포기는 언급하지 않았다. L과 O 모두 첫 결과를 받아들일 수 있는 반응이지만 느낌의 크기와 읽은 실마리는 같지 않다.

### 후보에 포함할 품질 범위와 반복 경험의 결정

O 정도의 말씀도 함께 넣을지, 연결이 더 좋은 말씀부터 모을지 질문하자 사용자는 **‘O 정도의 말씀도 넣어. 매번 같은 말씀이 뽑히는것도 별로일거 같아’**라고 답했다. 이 고민의 후보 묶음에 L과 O를 함께 남긴다. 조금 어렵거나 상대적으로 연결이 약해도 개인적 실마리·신비함을 얻고 다시 뽑을 필요가 없는 수준의 후보는 포함할 수 있다는 품질 범위를 반영한다.

말씀의 반복 경험도 만족도에 영향을 줄 수 있으므로 같은 구절만 계속 뽑히는 것은 피하고 싶다는 선호를 기록한다. 충분함 하나만으로 모든 구절을 통과시키거나 다양성 확보만으로 미검토·불충분한 구절을 넣는 기준을 채택한 것은 아니다. 후보에 남기는 결정과 같은 확률로 추첨하는 결정은 별개다.

후속으로 새로운 고민의 첫 뽑기에서는 최근 5번에 없는 충분한 후보에서 먼저 뽑고, 충분한 후보가 모두 최근에 본 말씀이면 다시 허용하기로 결정했다. 같은 고민의 다시 뽑기는 직전 구절을 제외하고, 후보가 부족하면 범위를 넓혀 다른 말씀을 제공한다. 구체 결정은 아래 12절에 기록한다. 이어 충분한 후보의 동일 확률 추첨을 14절에서 선택했다. 확장의 세부 조건, 사용자 식별·보관 방식, 통과 점수는 아직 정하지 않았다. 실제 추첨의 반복 빈도나 사용자별 피로를 측정한 자료도 아니다.

이번에는 G05의 검수 후보에 L과 O를 함께 남기기로 결정했다. 유사한 새 입력에서도 이 후보를 찾도록 하는 자동 선정 조건은 연결 근거와 반례를 검토해 공동 결정한다. 후보 수의 목표·통과 점수·추첨 가중치는 이 비교만으로 지정하지 않는다. 서비스가 사용자의 행동 방향을 고르는 규칙으로 바꾸지 않는다.

## 12. 새로운 고민의 첫 뽑기에서 반복을 줄이는 결정

사용자는 O 정도의 후보도 포함하고, 매번 같은 말씀만 나오는 경험은 피하고 싶다고 밝혔다. 새로운 고민의 첫 뽑기에서 최근 5번에 없는 충분한 후보를 우선하되 모두 최근에 본 말씀이면 다시 허용하자는 구체 제안에 **‘좋아’**라고 답했다. 아래는 첫 버전에서 사용할 합의된 규칙이며 아직 구현하지 않았다.

### 합의한 시작 방식

- 사용자에게 뽑기 결과로 실제 보여준 **최근 5번의 말씀**을 반복 여부를 확인하는 범위로 사용한다. 5번은 첫 버전의 시작값으로 채택했으며 이용 자료에서 검증된 최적값은 아니다. 실패한 요청이나 현재 인터뷰의 구절 비교를 실제 노출 이력으로 넣지 않는다.
- 현재 고민에 충분한 후보로 검수된 말씀들 중 최근 5번에 없는 후보가 있으면 그 후보들에서 뽑는다.
- 충분한 후보가 전부 최근에 본 말씀이면 그 후보들에서 다시 뽑을 수 있게 한다. 최근에 봤다는 이유로 해당 고민과의 연결이 불충분하거나 미검토인 말씀을 대신 넣지 않는다.
- 최근 5번은 추첨에 적용하는 범위다. 전체 기록의 보관·삭제 기간, 계정이나 사용자 식별 방식은 이 결정으로 정하지 않는다.

| 가상 조건 | 합의한 규칙의 동작 | 남는 한계 |
|---|---|---|
| 해당 고민의 충분한 후보가 L·O이고 L만 최근에 봄 | O에서 뽑음 | O가 해당 고민에서 검수된 충분한 후보라는 조건이 필요함 |
| 해당 고민의 충분한 후보가 L·O이고 둘 다 최근에 봄 | L·O에서 다시 뽑을 수 있음 | 같은 말씀의 반복을 완전히 막지는 못함. 후속 결정에 따라 둘 다 남으면 각각 50% |
| 해당 고민의 충분한 후보가 L 하나이고 최근에 봄 | L이 다시 뽑힐 수 있음 | 반복보다 이 고민에 대한 검수된 후보의 품질을 우선하는 예외 |

위 표는 가상 추첨 기록을 전제로 한 동작 설명이다. 실제 서비스를 이용해 L·O가 반복 노출된 기록이나 새로운 고민에 L·O를 적용한 평가 자료가 아니다. G05에서 받은 반응과 가상 동작을 구별한다.

### 같은 고민의 다시 뽑기에서 후보를 확장하는 결정

직전 구절만 남았을 때 같은 말씀을 다시 보여줄지 또는 짧게 알리고 기존 결과를 유지할지 질문하자, 사용자는 두 방식 대신 **범위를 확장해서 항상 다른 말씀을 뽑는 방식**으로 정정했다. 다시 뽑기는 현재 말씀이 마음에 들지 않아 하는 행동이므로 같은 말씀을 주면 안 된다고 설명했다.

재뽑기를 제공하는 경우에는 직전 구절을 모든 후보 단계에서 제외한다. 제외 후 후보가 부족하면 후보 범위를 넓혀 다른 말씀을 뽑는다. 같은 구절을 다시 주거나 후보가 없다는 안내로 뽑기를 끝내는 방식은 채택하지 않는다. 새로운 고민의 첫 뽑기에서 최근 5번의 말씀을 다시 허용하는 예외와, 같은 고민의 다시 뽑기에서 직전 구절을 금지하는 규칙을 구별한다.

사용자가 요구한 역할은 서비스가 특정 말씀을 정해 주는 것이 아니라, **효과를 기대할 수 있는 후보 묶음을 준비해 사용자가 무작위로 뽑을 수 있도록 돕는 것**이다. 좋은 경험을 보장하고 싶다는 목표를 보존하되 이미 효과를 검증하거나 보증한 서비스라는 사실로 기록하지 않는다. AI는 초기 ②의 고민 해석을 유지하고, 확장·추첨은 검수된 데이터와 프로그램 규칙으로 수행한다. 후보 수가 적다는 이유로 런타임 AI가 새 말씀을 추천·평가하는 ③으로 바꾸지 않는다.

| 다시 뽑기의 가상 조건 | 요구된 동작 | 상태 |
|---|---|---|
| 충분한 후보 L·O 중 방금 L을 봄 | 직전 L을 제외하고 O를 뽑음. O도 최근에 봤더라도 직전과 다른 후보임 | 채택한 방향 |
| 좁은 조건의 후보가 방금 본 L 하나뿐 | L을 제외한 채 범위를 넓혀 다른 말씀을 뽑음 | 후보 확장 채택. 세부 확장 조건은 공동 검토 |

### 후보 확장을 구체화할 설계 제안

1. 먼저 현재 고민의 구체 조건에 연결된 검수 후보를 찾는다.
2. 후보가 부족하면 물건·활동 같은 주제가 달라도 핵심 갈등이 닮은 검수 조합으로 범위를 넓히는 안을 검토한다. 입력에 명시된 제약과 미확인 조건은 그대로 보존한다.
3. 더 넓은 범위에서도 뽑을 수 있도록 여러 구체 고민에 대조한 기본 후보 묶음을 준비하는 안을 검토한다. 직전 구절 하나를 제외해도 다른 말씀이 남는 구성을 갖춰야 한다.
4. 확장된 후보들에서 프로그램이 무작위 추첨한다. 사용자의 선택 방향을 정답으로 미리 지정하거나 가장 좋은 한 절을 고정 추천하지 않는다.

위 단계·연결 조건·기본 후보의 구성과 검수 방식은 제안이다. 미검수 성경 전체를 대체 후보로 쓰거나, 항상 좋은 효과가 나는 후보 묶음을 이미 확보했다는 뜻이 아니다. G05에서 좁은 후보가 L만 남았다고 가정하면 이미 이 고민에서 충분하다고 평가한 O까지 확장하는 예로 설명할 수 있다. 실제로 좁은 조건이 L만 남기는 알고리즘을 구현했다는 근거는 아니다.

사용자는 **항상 말씀은 뽑혀야 한다**는 제품 요구를 명시했다. 최초 후보 부족 처리도 말씀을 제공하는 이 요구에 맞춰 설계하며, 후보 확장의 범위와 품질 검수는 함께 결정한다. 해석 오류·기술 오류의 구체 복구 방식과 재뽑기 버튼의 출시 범위는 별도로 남는다. 이상적으로 한 고민에 한 번이면 충분하되, 그 수준에 못 미치면 다시 뽑을 수 있도록 하자는 기존 방향은 유지한다.

반복 회피에 따른 실제 만족도, 후보의 부족 빈도, 뽑기별 후보·제외 이유는 배포 후 자료에서 함께 살필 제안이다. 서비스 안에 개선용 AI나 자동 가중치 변경을 추가하는 결정이 아니다.

## 13. 주제가 다른 사례로 후보를 확장하는 검토

후보 확장은 각 말씀에 새로운 `구체 고민 × 말씀` 연결을 추가하는 방식으로 검토한다. 원래 사례에서 좋은 반응이 있었다는 이유만으로 다른 고민의 후보 자격을 지정하지 않는다. 이번에는 판매 사례에 대조했던 M을 일정·과제 고민 G05에 제시했다.

### 확장 검토 기록의 형식 제안

| 연결 가설 | 계획·서두름에 관한 표현에서 이번 고민의 실마리를 읽을 수 있는지 대조함. 명시된 시간 부족을 조급한 성격·충동적 결정과 같게 처리하지 않음 |
| 새 조합의 평가 | 연결은 되지만 좋은지는 확신하지 못함. 콘서트를 빠지고 과제하기 또는 콘서트에 가고 늦게 제출하기를 떠올림. 조금 신비롭고 후련할 것 같으며 괜찮을지도 모른다고 예상함. 후속으로 첫 결과라면 그대로 둘 것 같다고 답함 |
| 적용 상태 | 첫 결과를 받아들일 수 있는 확장 후보로 검토 유지. 좋은지에 대한 확신을 더 높게 채우거나 기존 판매 사례의 평가를 새 고민의 평가로 옮기지 않음. 런타임 후보 조건은 미확정 |

위 기록은 데이터 형식·필드·분류 코드의 제안이다. 주제가 다른 사례를 찾는 일과 두 고민의 핵심 갈등이 실제로 닮았다는 판단도 구별한다. 사용자가 읽은 실마리를 받은 뒤 후보 연결 조건을 검토하며, 말씀의 개인적 선택 방향은 조합의 평가로 남긴다.

G05 × M에서는 두 방향의 실마리와 약간의 신비함·후련함이 생겨도, 사용자는 전체적으로 좋은 뽑기인지 확신하지 못했다. 후속으로 첫 결과라면 그대로 둘지 또는 다른 말씀을 뽑고 싶은지 물었고 사용자는 **‘그대로 둘거 같아’**라고 답했다. 전체 평가의 확신과 첫 결과를 받아들일 수 있음을 각각 보존한다. 여러 해석이 있다는 이유만으로 탈락시키거나 느낌이 있다는 이유만으로 최고 수준의 후보로 판정하지 않는다.

늦게 제출하는 선택은 말씀을 읽은 뒤 사용자가 떠올린 방향이다. 원래 입력은 오늘 마감이며 제출 기한이 바뀌거나 지각 제출이 허용된다는 정보가 없다. 이 반응을 최초 입력의 조건이나 실제 제출 행동으로 바꾸지 않는다. 마감·현실 결과와 개인적 해석을 구별한다.

### 범위를 넓힐 때 함께 확인할 사항

- 원래 입력의 양쪽 부담·기한·미확인 조건을 그대로 보존한다. 말씀에 맞추기 위해 입력을 고쳐 읽지 않는다.
- 새 고민에서 받은 충분함과 기존 고민의 충분함을 각각 기록한다. 느낌이 약해도 첫 결과로 충분할 수 있다는 기존 기준을 유지한다.
- 연결이 어려운 조합도 해당 말씀의 적용 범위를 검토하는 근거로 남긴다. 모든 주제에서의 탈락으로 바꾸지 않는다.
- 채택한 연결 조건을 초기 ②의 규칙에 추가하는 방식은 공동 결정한다. 런타임 AI가 확장 후보 말씀을 평가·추천하는 흐름으로 바꾸지 않는다.

G05에는 이미 L·O를 남기기로 결정했다. M의 새 반응을 통해 후보 묶음을 더 넓힐 수 있는지 검토한다. 이전 M의 긍정 반응과 G05의 L·O, 후보 확장 목적에 노출된 생성 사례 예상 평가라는 조건을 보존한다.

### 이번 대조에서 후보 연결 조건으로 옮겨볼 제안

G05의 확장 검토 후보로 M을 유지한다. 적용 조건 초안은 ‘하고 싶은 활동과 당일 마감인 미완료 업무 사이에서, 활동 후 남는 시간이 부족한 고민’이다. 대상 활동이 콘서트인지와 사용자가 실제로 조급하다고 말했는지는 별도로 보존한다. ‘조급함’이라는 단어가 입력에 반드시 있어야 한다는 조건을 이 반응만으로 지정하지 않는다.

입력의 표현이나 활동을 바꾼 새 사례에서는 핵심 갈등이 유지되는지, 같은 말씀에서 어떤 실마리가 생기는지를 다시 검토한다. 업무를 이미 마쳤거나 기한이 다른 사례도 반례 후보로 남긴다. 이 적용 조건·새 사례의 후보 자격은 제안이며 미평가 사례에 만족 반응을 채우지 않는다. 후보 확장을 특정 행동을 권장하는 규칙으로 만들지 않는다.

## 14. 충분한 후보의 동일 확률 추첨 결정

G05의 입력·AI 정보 정리·검수 후보·반복 규칙·추첨을 [전체 흐름 예시](concern-analysis-matching-proposal.md#8-g05의-입력부터-추첨까지-연결한-예시-2026-10-08)로 연결했다. L이 O보다 연결은 더 좋았지만 둘 다 첫 결과로 충분했던 반응을 바탕으로, 연결 경험이 더 좋은 후보에 조금 더 무게를 주는 방식과 같은 확률 방식을 비교했다. 최근 말씀 제외 규칙을 먼저 적용한다고 설명했고 사용자는 **‘충분한 후보는 모두 같은 확률’**을 선택했다.

첫 버전은 반복·확장 규칙 적용 후 남은 충분한 서로 다른 말씀 후보가 N개이면 각각 **1/N**로 뽑는다. L·O가 둘 다 남으면 각각 50%다. 같은 구절을 여러 검수 사례에서 찾았더라도 하나의 말씀 후보로 정리하며 발견한 연결 수를 확률로 옮기지 않는다. 새로운 고민의 최근 5번 회피·전체 후보가 최근일 때의 재허용, 같은 고민 재뽑기의 직전 제외와 후보 확장은 유지한다.

품질 차이·사용자 반응은 어떤 고민에서 충분한 후보인지 검토하는 근거로 남긴다. 현재 AI가 말씀별 점수·확률을 정하지 않고, 피드백으로 서비스가 자동 수정하지 않는다. 구절 ID·표시 범위의 식별, 후보의 필수 조건·배제 조건·통과 기준은 공동 결정 사항이다. M의 반응을 기록했다는 사실로 실제 후보 편입을 확정하지 않는다. 추첨 확률과 좋은 뽑기의 만족 확률은 구별한다.

## 15. 충분한 후보를 검수하는 기준의 초안

사용자의 다음 진행 요청에 따라 지금까지의 조합별 반응을 검수 질문과 기록 형식으로 정리했다. 남은 충분한 후보의 동일 확률 추첨은 확정됐다. 아래 질문·분류 상태·새 조합의 검토 절차는 공동 검토할 제안이며 수치 통과 기준이나 서비스의 설문 화면을 결정한 것은 아니다.

### 검수할 단위와 경험의 확인

검수 단위는 **고민 원문·조건 × 정확한 판본과 제시 범위의 말씀**이다. 사용자가 말씀에서 읽는 연결과 선택의 실마리를 먼저 확인한다. 짧게 생각해서 연결할 수 있는 후보도 포함하며, 사용자가 원래 원하는 선택과 같은 방향이어야 한다는 조건은 두지 않는다.

| 검수 질문의 제안 | 살펴볼 근거 | 기존 반응에서 보존할 경계 |
|---|---|---|
| 원문을 읽고 자신의 고민과 연결된 실마리를 스스로 얻을 수 있는가? | 고민의 어떤 부담·조건과 말씀의 어떤 부분을 연결했는지 | 표면적인 단어 일치와 연결을 구별. 짧게 생각하는 것은 허용하되 연결 해설 뒤의 반응은 별도 기록 |
| 그 실마리가 실제 망설임에 어떤 방향을 주는가? | 선택·기울어진 마음·결심으로 이어진 사용자 표현 | 한 방향으로 바로 확정하지 않아도 됨. M처럼 여러 방향을 떠올릴 수 있음. 서비스의 행동 결론으로 바꾸지 않음 |
| 자신의 상황에 들어맞는 신비함·뜻밖의 느낌이 있는가? | 사용자가 표현한 신비함·놀라움과 그 이유 | 느낌의 크기를 각각 기록. 해석이 가능하다는 이유만으로 신비했다고 채우지 않음 |
| 이 말씀을 첫 결과로 받아들일 만큼 충분한가? | 충분함·그대로 두겠음·다시 뽑고 싶음에 대한 직접 반응과 조건 | O·F처럼 느낌이 약하거나 즉시 후련하지 않아도 충분할 수 있음. 무응답과 미확인은 부정으로 채우지 않음 |

최소 후보의 경험을 **자신의 고민에 연결된 실마리, 어느 정도의 신비한 적합함, 한 번의 결과를 받아들일 수 있는 만족**으로 설명하는 안을 제안한다. 후련함의 크기와 시점은 별도 항목으로 남긴다. 모든 고민에서 즉시 갈등이 끝나거나 단호한 결정을 해야 통과한다는 기준은 제안하지 않는다. 위 세 요소의 구체 판정 방법과 배포 후보의 통과 기준은 공동 결정 사항이다.

본문 이해의 어려움도 따로 기록한다. 사용자가 원문의 모든 단어를 정확히 풀이하지 못하더라도 직접 실마리를 읽을 수 있었던 F의 반응을 보존한다. 반대로 어휘 풀이 후 좋은 반응이 나온 G를 원문만 읽은 성공으로 옮기지 않는다. 서로 다른 판본의 반응도 합치지 않는다.

### 기존 사례를 검수 기준에 대조하기

| 조합 | 이미 받은 근거 | 검수에서 다룰 제안 |

이 표는 기존 반응을 정리한 것이며 새로운 사용자 평가나 자동 통과 결과가 아니다. 생성 사례, 실제 고민에 대한 기획 단계 예상 평가, 배포 후 사용한 결과의 피드백을 각각 구별한다. 현재 표에 실제 서비스 사용 후 피드백은 없다.

### 본문과 경험의 검수를 함께 보존하기

- 본문·절·판본·제시 범위·출처의 정확함과 앞뒤 문맥을 확인한다. 사용자의 개인적 해석을 원문의 확정된 뜻이나 행동 명령으로 설명하지 않는다.
- 사용자에게 원문이 개인적으로 읽힌 방향은 그대로 기록한다. D의 넉넉한 허용 같은 느낌을 반어법의 확정 해석으로 바꾸지 않는다.
- 초기 입력의 선택지·양쪽 부담·명시된 기한과 미확인 조건을 보존한다. 긍정 반응을 얻기 위해 입력에 희소성·재정 여력·지각 허용을 추가하지 않는다.
- 연결 조건을 일반화할 때에는 표현이 달라도 같은 갈등인 사례, 같은 주제지만 부담·기한이 달라진 사례, 다른 주제지만 연결이 가능한 사례를 대조한다. 미검토 사례의 만족을 미리 채우지 않는다.
- 서비스에 쓸 본문의 확보·이용허가 상태는 정확한 표본 확인과 별도로 관리한다.

| 제시 조건 | 설명 전/풀이 후, 이전 구절 노출·비교 목적, 실제 고민/생성 사례 |
| Codex의 사전 판단 | 연결 가설, 확인할 부담, 난해할 부분, 적용 조건·반례 제안. 사용자 반응과 구별 |
| 사용자의 반응 | 원문 표현, 직접 읽은 연결·실마리, 신비함, 즉시/예상 후속 후련함, 첫 결과의 충분함·조건 |
| 판단의 근거 출처 | Codex의 사전 예상 / 사람이 원문을 읽은 사전 반응 / 실제 서비스 이용 후 피드백 |
| 조합의 검토 상태 | 초안 / 공동 검토 중 / 해당 조건에서 후보로 남기기로 결정 / 해당 조합의 긍정 근거 부족. 상태 이름은 제안 |
| 적용할 범위 | 필수 조건·배제 조건·미확인 조건의 처리, 연결한 반례와 검수 버전. 실제 규칙 편입 여부를 별도 기록 |

좋음·나쁨의 단일 점수로 합쳐 미확인·조건부·풀이 효과를 숨기지 않는다. 연결 가능성만 확인됐거나 원문에 없는 정보에 기대는 조합, 좋은지를 확신하기 어렵다는 조합은 이유와 함께 검토한다. ‘다시 뽑지 않겠다’는 반응만으로 나머지 경험 항목을 자동 채우지 않는다.

### 새 조합을 처음 제공하기 전의 검토 방식 비교

다양한 구체 고민과 말씀을 늘릴 때 모든 조합에 사용자의 직접 반응을 먼저 받을지, Codex가 사전 검수한 초안에서 대표 표본·경계 사례·실패 예상 사례를 함께 검토한 뒤 후보 묶음을 채택할지를 공동 결정한다.

| 비교할 운영 방식 | 진행 | 얻는 근거와 남는 한계 |
|---|---|---|
| Codex의 사전 검수 후 표본과 경계 사례를 함께 검토 | 여러 구체 조합의 초안·연결 조건·반례를 만들고, 사람이 읽을 표본과 불확실한 사례를 검토해 묶음을 채택 | 후보를 넓힐 수 있음. 직접 읽어보지 않은 조합의 판단은 계속 사전 예상이며 실제 만족으로 표시하지 않음 |
| 모든 조합에서 직접 읽은 사전 반응을 확인 | 새로운 조합마다 사용자 또는 검토자가 원문을 읽고 느낀 반응을 받은 뒤 후보로 남길지 결정 | 조합별 사람의 경험 근거가 있음. 후보를 넓힐 때 모든 조합의 검토가 필요하며 배포 후 만족을 보장하지는 않음 |

첫 방식으로 초안을 넓히고 표본·경계 사례를 함께 검토하는 안을 제안한다. 후보 수·필수 표본 범위·통과 기준·검토자의 구성은 아직 정하지 않았다. 어느 방식을 택해도 실제 반응을 대신 만들어 넣지 않으며, 새 후보 묶음과 규칙의 적용은 공동 결정한다. 서비스 안에 개선용 AI를 넣거나 런타임 ②를 ③으로 확대하지 않는다.
